# 服务中心

基于 Tauri 2、React、TypeScript 和 Rust 的本地服务控制台。根据已确认的[深浅双主题设计](./docs/design/设计说明.md)实现，服务目录、环境、进程、端口、独立终端与文档集中管理。

## 功能

- 手动添加本地命令型服务，关联工作目录、已有 Python venv 或自定义环境，配置启动命令、搜索路径、环境变量与预期端口。
- 添加前端项目，识别 `package.json` 中的脚本与包管理器；添加静态目录，使用内置独立预览进程；通过系统浏览器查看页面。
- 添加 Windows `.exe` 或 macOS `.app`，发现没有监听端口的运行中应用，统一显示、关联和请求退出。退出中心或删除应用记录时保留桌面应用运行。
- 从“发现服务”按 TCP 监听和 UDP 绑定端口查看已有进程，筛选系统／非系统／待确认项，选择接入并添加备注、文档。外部进程退出平台后继续运行。
- 启动、停止和重启受管服务，分开展示进程状态、真实端口和预期端口冲突。停止服务不结束其独立终端或 Agent 会话。
- 每个服务可打开多个真实 PTY 终端。内置 Codex、Claude Code、Gemini CLI 启动配置，也可使用自定义 CLI。工具沿用自身安装与登录配置。
- 为服务保存备注和多篇 Markdown 文档，支持编辑、预览与导出。切换服务保留文档草稿；文档预览不执行原始 HTML。
- 深色、浅色和跟随系统主题；关闭窗口留在托盘，选择“停止托管服务并退出”后清理命令服务、前端服务、静态预览与独立终端，保留桌面应用。

首次启动是空服务列表，不自动创建演示服务、运行命令或安装 Agent。

## 开发环境

需要 Node.js 22.12+（建议当前 LTS）、pnpm 11+ 和 Rust 稳定版。

- macOS：需要 Xcode Command Line Tools，应用目标为 macOS 13+。
- Windows：需要 Microsoft C++ Build Tools 的“使用 C++ 的桌面开发”组件、Rust MSVC 工具链与 WebView2，应用目标为 Windows 10 22H2／Windows 11 x64。

### 一键启动调试

- **macOS：** 在 Finder 双击项目根目录的 [启动调试.command](./启动调试.command)。也可以在终端执行 `./启动调试.command`。
- **Windows：** 双击项目根目录的 [启动调试.bat](./启动调试.bat)。

脚本会定位项目目录、检查 Node.js／pnpm／Rust、按锁文件同步前端依赖，然后执行 `pnpm desktop`。前端修改自动更新，Rust 修改由 Tauri 重新编译；首次编译可能需要几分钟。系统工具缺失时会显示中文提示，不会自动安装编译器或修改全局环境。

macOS 支持从常见安装目录和 nvm 查找已有 Node；本机仍保留前次构建的临时 Rust 时也可自动复用，无需手动设置环境变量。临时工具链被系统清理后需要安装常规 Rust。

调试数据默认保存在项目的 `.local-dev/data`，与正式安装版分开，并已加入 Git 忽略规则。已设置 `KACENT_DATA_DIR` 时沿用该路径。关闭应用窗口会隐藏到托盘；结束调试时先选择托盘中的“停止托管服务并退出”。启动失败时查看终端日志；脚本不会自动结束占用 1420 端口的其他程序。

应用采用单实例模式：若正式版或另一个调试实例已在托盘运行，请先退出该实例，再启动调试。

只检查启动环境，不安装依赖或打开应用：

```sh
# macOS
./启动调试.command --check
```

```powershell
# Windows，仅对这次本地脚本执行指定策略，不修改系统设置
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-dev.ps1 -Check
```

也可以手动安装前端依赖并运行桌面应用：

```sh
pnpm install
pnpm desktop
```

仅开发界面时运行：

```sh
pnpm dev
```

浏览器开发页位于 `http://127.0.0.1:1420`。它具有明确的预览提示，使用独立的浏览器存储，不能启动本机进程。访问 `http://127.0.0.1:1420/?demo=1` 可在尚无预览存储时载入示例配置；示例不会写入桌面数据库，也不伪造运行中的服务。

## 构建与验证

```sh
pnpm build
cd src-tauri
cargo check --all-targets
cargo test
cargo run --example runtime_smoke
cargo run --example discovery_smoke
```

真实进程验收程序在独立临时目录中创建两个测试服务，检查中文与空格目录、环境隔离、真实端口、重复启动、交互输入、超过缓存容量的输出、子进程清理及真实 Agent CLI 的版本调用。所有路径都会尝试清理所创建的进程；失败时保留临时数据用于排查。它不发起模型请求，也不操作用户已有服务。

本轮多类型功能的定向验收入口（在 `src-tauri` 目录执行）：

```sh
cargo run --example frontend_smoke
cargo build --bin kacent-center
cargo run --example static_sites_smoke -- target/debug/kacent-center
# macOS：编译并控制临时 Cocoa 应用，需 Xcode Command Line Tools
cargo run --example application_smoke
```

前端验收需要已有 Node.js、npm 和 pnpm；不会自动安装依赖。Windows 的静态 helper 路径应使用 `target/debug/kacent-center.exe`。各平台实际覆盖范围见[验证记录](./docs/验证记录.md)。

平台安装包分别在对应操作系统上构建：

```sh
# macOS
CI=true pnpm tauri build --bundles app,dmg

# Windows
pnpm tauri build --bundles nsis
```

输出位于 `src-tauri/target/release/bundle/`。安装后的应用不依赖 Node.js 或 Rust；被管理服务自己的运行时与 Agent CLI 仍需安装在本机。首版不配置签名、公证或自动更新。

macOS 的 `CI=true` 会跳过 DMG 的 Finder 外观自动化，保留应用与 Applications 拖放入口。若受限开发沙箱中的 `hdiutil` 报“设备未配置”，应在具有磁盘映像操作权限的普通系统终端打包；无需修改应用代码或系统安全设置。

## 使用说明

1. 选择“新增服务”，先选择服务类型。命令服务填写工作目录与启动命令；其他类型的配置见下方说明。需要 Python 环境时选择已有 venv 根目录；其他运行时可配置自定义可执行文件目录。
2. 预期端口是检查目标；要改变程序的实际端口，需要修改启动命令或程序自身配置。
3. 创建服务后点击“启动”，在“服务输出”中查看运行结果；点击“新建终端”可获得独立会话。
4. 在“AI 工具”中配置 CLI 路径和参数。参数列表每行一个完整参数，保留参数内部空格，不自动拼接成未转义的 shell 命令。
5. 从服务顶部“打开 Agent”选择工具。关闭一个终端只影响该会话；删除服务会明确提示将结束的全部会话。
6. 文档默认保存到本机应用数据库；需要让 Agent 读取时导出 Markdown，再在终端中引用文件路径。

### 发现与接入现有服务

1. 点击左侧“发现服务”，默认显示非系统及待确认进程。搜索端口、进程名称、PID 或路径，查看每个进程持有的全部监听／绑定端口。
2. PostgreSQL 等服务的主进程与工作进程，在确认属于同一进程族后合并为一条服务项；相同协议和端口集中展示，保留各地址及所属 PID。展开可查看成员，搜索某个成员端口或 PID 也会显示完整分组。同名但独立运行的服务不会自动合并。
3. 从分组接入主进程，或打开成员“详情”后选择接入，填写名称、备注和可选工作目录；启动命令可以之后再补齐。分组只集中展示端口，接入和停止仍明确作用于选中的 PID。已接入主进程时可以直接打开已有服务，无需逐个添加工作进程。
4. 系统内建组件与待确认项默认受保护，可明确解除当前实例的保护；共享宿主始终只读。解除保护不提升操作系统权限，应用重开后恢复保护。
5. 外部停止只作用于所选进程，不结束其父进程、子进程或整个进程组。macOS 先请求退出，五秒后可强制终止；Windows 使用进程终止操作。后台管理器可能重新拉起程序，需要重新选择新实例。
6. 原来的终端输出不能接回；填写有效工作目录后可以新建独立终端或 Agent。补齐并确认启动命令、目录和环境后，使用“转换为平台托管并启动”创建新的受管实例。
7. 删除外部记录只解除关联，退出平台也保留原外部进程。平台新建的关联终端仍按正常退出规则清理。

发现功能仅在桌面应用可用。TCP 显示监听，UDP 显示绑定；进程运行、端口存在都不等同于服务健康。权限限制或扫描失败会明确标注，不能用空结果推断进程已经退出。

### 前端项目与静态站点

新增服务时选择“前端项目”，选取包含 `package.json` 的目录，读取并确认包管理器与脚本。支持 npm、pnpm、yarn、bun；优先采用 `packageManager` 声明，否则依据唯一锁文件判断。无法判断时手动选择。脚本原文只用于展示，点击启动前不会运行；应用不自动安装运行时、依赖或构建项目。

启动后可查看服务输出、实际端口，通过“打开页面”进入系统浏览器。可配置固定访问地址；未配置时从本实例的 TCP 监听端口提供候选入口。候选地址使用 HTTP，使用 HTTPS 或特定路径的项目请填写实际访问地址。端口存在不代表页面已就绪。

选择“静态站点”时填写包含 `index.html` 的构建目录。默认只监听本机 `127.0.0.1`，端口填 `0` 自动分配，指定端口占用会报错。单页应用回退仅用于页面导航，缺失的脚本、样式等资源仍报告错误。此模式不运行 SSR、后端 API 或构建命令；这类项目应使用前端项目或命令服务。

每个静态站点使用独立的内置子进程，不需要额外安装 Node 或 Python。停止某个站点不影响其他站点；退出中心会停止全部静态预览。前端项目和静态站点重开中心后不会自动启动。

### 桌面应用

新增服务时选择“桌面应用”，选取当前系统的 `.exe` 或 `.app`。可以配置启动参数；Windows 支持独立的应用启动目录。工作目录可留空，填写后用于普通终端与 Agent；macOS 通过系统应用启动接口打开 `.app`，此字段不改变应用本身的工作目录。复用已有实例时，新参数和环境变量不会改变它的既有运行环境。

“发现服务”的“运行中应用”视图也包含没有监听端口的应用。关联时核验 PID、原生创建时间和实际路径，不会因为进程同名就接管。已存在唯一同路径实例时，启动操作优先复用；多个实例需要选择。启动器退出且不能可靠确认交接目标时显示待关联，需明确选择实际实例。

“显示应用”请求系统激活应用或恢复窗口，操作系统可能限制前台切换，没有可显示窗口时会说明原因。“请求退出”保留应用自己的保存提示；等待五秒仍未退出时不会自动强杀。强制结束是单独确认的操作，仅针对关联主进程，可能丢失该应用未保存内容。重启必须先确认旧实例退出。

退出中心和删除应用记录都会保留桌面应用；删除时只关闭中心创建的关联终端。中心重开后仅恢复身份仍匹配的原实例，已经退出并被重新启动的实例不会自动继承旧关联。系统和待确认应用沿用发现页的保护规则，权限不足不会自动提权。

## 数据与运行边界

Rust 在系统应用数据目录下使用 `services.sqlite3` 保存配置、文档和偏好，外部关联保存 PID 与精确创建身份，任何控制前重新核验，不能按端口或 PID 自动接管新实例。开发验收可通过 `KACENT_DATA_DIR` 指定隔离数据目录。删除服务不会删除工作文件夹或环境文件夹。

本应用管理自己启动的前台命令型服务，也能观察和接入外部正在运行的进程。关闭窗口不结束应用；明确退出后再次打开恢复配置及仍匹配的外部关联，不自动启动服务或恢复旧终端进程。本期不修改 launchd／Windows 服务管理器的注册、自动启动或重启策略，不接管 Docker，也不承诺控制主动脱离受管会话的守护进程。

不同终端具有独立的当前目录、环境和输出缓冲，但不是文件系统沙箱。用户选择的程序仍以当前系统账号运行。

## 代码结构

- `src/App.tsx` 与 `src/components/`：工作台、配置抽屉、文档与终端组件。
- `src/api.ts`、`src/types.ts`：前后端调用和共享消息结构；浏览器预览适配与桌面执行明确分开。
- `src/terminals.ts`：跨页面保留的 xterm 实例、有序输入和消费确认。
- `src-tauri/src/lib.rs`：Tauri 命令、单实例、托盘和退出协调。
- `src-tauri/src/store.rs`：SQLite 迁移、配置与文档持久化。
- `src-tauri/src/discovery.rs` 与 `discovery/`：共享端口扫描、分类证据、平台进程身份与单进程终止。
- `src-tauri/src/external.rs`：外部关联、临时保护、状态刷新与转换托管。
- `src-tauri/src/runtime.rs` 与 `src-tauri/src/runtime/`：PTY、环境解析、端口归属、进程树清理与有界输出。
- `src-tauri/src/projects.rs`：前端项目脚本与包管理器识别。
- `src-tauri/src/static_sites.rs`：独立静态预览进程、目录访问约束与 HTTP 生命周期。
- `src-tauri/src/applications.rs` 与 `applications/`：桌面应用发现、实例关联和平台原生控制。

关键隔离、生命周期与数据保护逻辑包含中文注释。交付前的检查结果记录在 `docs/验证记录.md`；代码等待人工 review，不自动执行 Git commit。
